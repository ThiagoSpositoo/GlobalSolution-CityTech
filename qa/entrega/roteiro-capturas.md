# Roteiro de capturas reais

1. URL do projeto e Backlogs com a hierarquia 5 Epics → 12 Features → 39 PBIs.
2. Descrição e critérios de aceite de **cada** Feature.
3. Descrição e critérios de aceite de **cada** PBI.
4. Features com seus Test Cases vinculados.
5. Summary completo de cada Test Case.
6. Steps estruturados de cada Test Case, com ação e resposta esperada.
7. Test Plan, Suites e casos atribuídos, se a licença permitir.
8. Execuções manuais reais com resultados.
9. Bugs reais vinculados, caso existam.
10. Relatórios analíticos do Test Plans para a apresentação.
11. Tela de permissões que comprove o professor como ADMIN, ocultando e-mails quando necessário.

Antes de capturar: confirmar URL, data, item e zoom legível. Depois: remover tokens, senhas, cookies, dados pessoais e abas alheias. Nome sugerido: `<ordem>_<tipo>_<id>_<descricao>.png`.

Não fabricar capturas nem usar a existência do roteiro como evidência.
